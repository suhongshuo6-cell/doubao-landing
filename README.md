# 豆包 Doubao · 立绘滚动剧场

**一个单页、无跳转、零构建的 WebGL 品牌落地页**

首屏就是一张铺满屏幕的立绘大脸 → 鼠标划过／按住可以在她脸上"捏"出弹性形变 →
向下滚动，取景从脸一路下移到赤足 → 左右拖拽，她会从正面转到侧面、背面。

`three.js` · 自写 GLSL · 明亮棚拍主题 · 无闪光特效 · 可直接托管到 GitHub Pages

## 设计原则

这个项目在视觉上有一条明确的底线：**要「交互炫、运镜炫」，不要「颜色炫、乱闪炫」**。

- 滚动驱动的景别变化（大特写 ↔ 中景 ↔ 全身）
- 捏脸的弹性物理（高斯收缩形变 + 欠阻尼弹簧回弹）
- 左右拖拽的转身（横向压缩 + 三视图混合，像真的转过去）
- 极慢的呼吸补光（周期 7.2s，幅度 1.3%）、指针视差、磁吸按钮、卡片随滚动淡入
- 光标语义（脸上是「捏」、可拖区是「拖」）
- **没有** bloom 爆闪、扫描线、色相乱跳、霓虹光晕、高频 pulse
- **没有**粒子特效（首版那套粒子汇聚已经移除）

配色也做了减法：浅灰米白棚拍底 + 深灰字 + **只有围巾红一个点缀色**，且只用在进度刻度、主按钮、捏脸光标这种小面积上。

## 快速开始

ES Module + importmap 需要 HTTP 协议，**不能直接双击 `index.html`**（`file://` 会被 CORS 拦截）。任选一种起服务：

```bash
# Python（macOS / Linux 自带）
python3 -m http.server 8080

# Node
npx serve -l 8080

# PHP
php -S 127.0.0.1:8080
```

打开 <http://127.0.0.1:8080>。不需要 `npm install`，不需要 build。

## 如何替换立绘

**三张图就是全部主角。** 换掉它们，整站视觉就换了。

### 1. 放文件

把三张**同一相机、人物绕自身中轴转**的立绘放进 `assets/character/`：

```
assets/character/front.png   # 正面
assets/character/side.png    # 侧面
assets/character/back.png    # 背面
```

对图的要求：

| 项 | 要求 |
|---|---|
| 构图 | 三张**垂直位置对齐**（头顶／脚底在同一条水平线上），人物大致居中 |
| 背景 | 干净的浅色棚拍背景（取景超出原图时页面用边缘像素延展，背景越均匀越无痕） |
| 比例 | 建议 16:9；正面那张要**头和脚都拍全**（全身分镜要看到整个人） |
| 分辨率 | **越高越好**。示例图只有 1280×720，大特写是靠预处理放大撑住的；换成 2560×1440 或更高，特写会明显更锐 |
| 姿势 | 三张姿势一致，转身时才不会"跳" |

### 2. 跑预处理

```bash
python3 tools/prepare-portrait.py            # 默认放大 2 倍 + 反锐化，输出 webp
python3 tools/prepare-portrait.py --scale 1  # 原图已经够大就跳过放大
```

脚本会输出每张图的实际倍数与体积，并打印**画面边缘的背景色**（可用于校准 `PALETTE.studio`）。

> 页面优先加载 `.webp`，找不到自动回退 `.png`；两张都没有时画面会显示一张写清楚"该放什么、放哪"的占位图，而不是白屏。

### 3. 对齐取景（重要）

`src/config.js` 里的取景坐标全部以**原图像素**为基准（默认 1280×720）。换了构图不同的图，需要重新量这几个量：

```js
export const PORTRAIT = {
  imgW: 1280, imgH: 720,   // 取景基准尺寸
  cx: 645,                 // 人物中轴（转身枢轴，也是取景的水平中心）
  faceBox: { x0: 596, x1: 700, y0: 20, y1: 98 },  // 面部命中框（决定哪里能捏脸）
};
```

量法：跑 `tools/preview-frames.py`，它会打印每个分镜实际看到的画面尺寸与"头部占屏比例"；也可以在 `tools/framing.py` 里改坐标后重新生成预览图，肉眼确认。

```bash
python3 tools/preview-frames.py --w 1600 --h 900                       # 桌面 10 个分镜 + 拼图
python3 tools/preview-frames.py --w 390 --h 844 --out .preview/phone   # 手机竖屏
python3 tools/preview-frames.py --view side                            # 换视角
```

预览用的是和 shader **完全同一套取景映射**（直接从 `src/config.js` 读参数），所以你看到的就是页面会渲染的构图。

## 部署到 GitHub Pages

**方式一：从分支直接发布（最简单，无需 CI）**

1. 推到 GitHub 仓库的默认分支（`main`）。
2. **Settings → Pages → Source** 选 `Deploy from a branch`。
3. 分支选 `main`，目录选 `/ (root)`，保存。
4. 访问 `https://<用户名>.github.io/<仓库名>/`。

> 所有资源都用**相对路径**，所以在 `用户名.github.io/仓库名/` 这种子路径下也能正常工作，不需要改 base。

**方式二：GitHub Actions** —— 仓库已含 `.github/workflows/pages.yml`，把 Pages 的 Source 改成 `GitHub Actions` 即可，之后每次推送 `main` 自动发布。

## 交互与分镜

页面共 10 个分镜，滚动进度 `p` 与取景、文案、HUD 一一对应：

| # | 分镜 | 取景 | 交互 |
|---|---|---|---|
| 00 | 开场 | 大脸特写（头部占屏 83%） | 开场只做一次推近 + 对焦；点击／空格／`Esc` 可跳过 |
| 01 | 面容 | 更近的脸（头部占屏 96%） | **捏脸**：按住拖动；划过即浅凹陷 |
| 02 | 颈肩 | 头 + 围巾 | — |
| 03 | 心意 | 围巾 + 上衣 | — |
| 04 | 腰线 | 腰腹 + 肚脐 | — |
| 05 | 手臂 | 中景（含双臂与手） | **左右拖拽转身** |
| 06 | 长腿 | 大腿 → 膝盖 | 拖拽转身 |
| 07 | 赤足 | 双脚与地面 | 拖拽转身 |
| 08 | 全身 | 整个人 | 拖拽转身；四张卖点卡 |
| 09 | 下载 | 整个人 + 留白 | 磁吸按钮、二维码、页脚 |

全局交互：

- **捏脸** —— 指针落在面部区域且脸足够大时启用。按下是**高斯收缩形变**，并依据形变的雅可比行列式反推明暗（被压进去的地方偏暗、周围被拉伸的地方偏亮），所以看着是"捏出一个软窝"而不是图片被错位。松手是**欠阻尼弹簧**，会有 1~2 次可见余振。全程没有任何闪光反馈。
- **转身** —— 在非面部区域横向拖动，正面 ↔ 侧面 ↔ 背面连续转动。转身用「横向压缩 + 两视图加权混合」，压缩到接近 0 时才切换，所以不会有重影；松手吸附到最近视图并回弹（欠阻尼，轻微过冲）。
- **视差** —— 指针位置驱动立绘极小幅位移（±7 原图像素），带来"活着"的感觉。
- **键盘** —— `↑/↓`、`PgUp/PgDn`、`Home/End` 推进分镜；`←/→` 转身。
- **光标** —— 脸上变红色「捏」，可拖区变「拖」，UI 上放大。
- **音效** —— 右上角开关（低频 pad + 捏脸音点，需用户手势，符合自动播放策略）。
- **画质** —— 右上角太阳图标，高／中／低循环。

## 技术实现

### 1. 一切都是「取景」

页面主体其实是**一整块全屏四边形 + 一个片元着色器**，没有 3D 人体。滚动只是改变"取景框"：从原图的哪一块采样、采样多大。

```glsl
// 屏幕 uv → 原图像素
vec2 screenToImg(vec2 s) {
  return vec2(uView.x + (s.x - 0.5) * 2.0 * uView.z,   // x
              uView.y + (0.5 - s.y) * 2.0 * uView.w);  // y（从上往下）
}
```

好处是任何放大倍率下都**逐像素精确**，不存在网格分辨率问题；而且这个映射是轴对齐线性的，所以 `tools/preview-frames.py` 用「裁剪 + 缩放」就能离线复刻出完全一样的构图来验证。

### 2. 转身：压缩 + 混合

```glsl
// 绕人物中轴横向压缩：转到 90° 时几乎缩成一条线
img.x = uCx + (img.x - uCx) / max(uSquash, 0.045);
```

`uSquash = |cos(t·π)|`，同时两视图做窄窗口交叉淡入淡出。因为切换发生在压缩到接近 0 的时刻，所以**看不到重影**，观感就是人真的侧过去了。三个视图的加权混合在 JS 侧算好归一化权重传进来，未用到的视图不产生纹理采样。

### 3. 捏脸：形变 + 由形变反推明暗

```glsl
img -= d * k;                        // 向按压点收缩（k = 强度 × 高斯）
float det = ax * ay - axy * axy;     // 形变雅可比行列式
float shade = 1.0 - 0.30 * clamp((1.0 - det) * 3.4, 0.0, 1.0)
                  + 0.11 * clamp((det - 1.0) * 2.6, 0.0, 1.0);
```

面积被压缩的地方（`det < 1`）压暗，被拉伸的地方（`det > 1`）提亮 —— 这一步是"有体积感"的关键，否则看起来只是图片被拉扯。

松手回弹用标准欠阻尼弹簧（`k=330, c=15`，阻尼比 ≈ 0.41），所以有可见余振。悬停时强度只有按下的四分之一，形成"划过也会轻微凹陷"的手感。

### 4. 取景锚点绑在 DOM 上

```js
const center = el.offsetTop + el.offsetHeight * 0.5 - window.innerHeight * 0.5;
p_beat = center / scrollLen;
```

每个分镜的锚点由该 `<section>` 在文档里的**真实位置**算出，段内用 `easeInOutCubic` 插值 —— 镜头会在每个分镜处自然减速停顿，像分镜脚本；改文案、调区块高度也不会让取景和文字错位。

### 5. 棚拍调子

片元着色器最后做一轮极轻的影调处理：曝光、轻 S 曲线（让肤色通透）、**极慢呼吸补光**（7.2s 周期、1.3% 幅度）、极淡暗角、按 8Hz 更新的低幅颗粒（0.012，避免逐帧抖动）。高倍特写时（可见高度 < 260 原图像素）额外做一次轻反锐化，抵消原图放大的软。

整条管线在**显示空间**做图像处理（`THREE.ColorManagement.enabled = false`），不走线性工作流 —— 对"照片合成"这类任务这才是不引入色偏的做法。

## 自检工具

```bash
node tools/scene-check.mjs
```

不需要浏览器，在 Node 里跑完整套校验，共 7 组：

| 组 | 内容 |
|---|---|
| A | 立绘资源是否就位、取景基准尺寸是否一致 |
| B | 10 个分镜取景是否覆盖「脸→颈→胸→腰→腿→脚→全身」且顺序单调；首屏头部占屏比例 |
| C | 捏脸命中框是否落在头部范围内、按压半径／强度／拖拽灵敏度是否合理 |
| D | 取景数学：屏幕 ↔ 原图像素映射、竖屏收窄、捏脸启用门控 |
| E | **着色器 uniform / varying 交叉审计** |
| F | 可选模块（程序化数字人）仍可构建、几何健全 |
| G | 明亮主题：亮度、对比度（WCAG）、无深色残留、无 <4s 高频动画 |

> **E 组为什么重要**：three 的 `WebGLUniforms.upload()` 里直接写 `v.needsUpdate`，**没有空值保护**。只要着色器里声明了某个 active uniform、而 `material.uniforms` 里没给，渲染那一刻就会抛异常 → 整个页面黑屏。这类问题在浏览器里很难一眼看出原因，但这套静态审计能直接点出来。开发过程中它确实抓到过包括这条在内的多个致命问题。

## 调参指南

**改主题色** —— `src/config.js` 的 `PALETTE`，以及 `styles/main.css` 顶部的 `:root`。

**改取景（最重要）** —— `src/config.js` 的 `BEATS[].frame`：

```js
{ id: 'waist', frame: { cy: 246, w: 300 } }
//                     ↑ 中心高度（原图像素，从上往下）
//                                ↑ 可见宽度（原图像素）
```

`cy` 越大取景越靠下，`w` 越小放得越大。改完跑 `python3 tools/preview-frames.py` 立刻能看到新构图。

**改捏脸手感** —— `PORTRAIT.pressRadius`（作用范围）、`pressMax`（按下强度）、`pressHover`（划过强度）；回弹软硬在 `src/three/interact.js` 的 `k2 / c2`（`c2` 越小余振越多）。

**改转身手感** —— `PORTRAIT.turnDragPx`（拖多少像素转 90°）、`PORTRAIT.turnSpring`。

**改气息** —— `INTRO.breathe` 与 `breathePeriod`；`QUALITY.*.grain` 控制颗粒。

## 可选模块：程序化数字人

仓库里仍然保留了**完全由代码生成**的数字人（头部球面变形 + 解析挖眼裂、程序化虹膜、各向异性头发、放样躯干四肢等），它有自己的配置 `src/legacy-config.js`，**页面默认不加载**（`main.js` 不 import 它，对首屏体积零影响），由 `tools/scene-check.mjs` 的 F 组持续保证可构建。

如果你想切回代码生成的角色，入口是 `src/three/character.js` 的 `buildCharacter()`；配套的几何原语在 `geometry.js`，着色器在 `shaders.js`。

> 注意：程序化角色当初是配深色主题调的光照，换成明亮主题后需要重新调光才能融进棚拍底色。

## 性能与降级

- 页面主体只有 **1 个 draw call**（全屏四边形）、2 个三角面 —— 成本全在片元着色器上。
- 高档位一次采样 3 张纹理；只有在**高倍特写**（可见高度 < 260 原图像素）时才额外做 4 向反锐化采样。
- DPR 上限：high 2.0 / medium 1.5 / low 1.0；移动端与低配机自动选 medium。
- 连续 2 秒低于 26fps 自动二次降级（DPR → 1、关锐化、颗粒降到 0.004）。
- `prefers-reduced-motion: reduce`：跳过开场，直接展示静态成品画面。
- 无 WebGL2：显示兜底卡片，DOM 内容完整可读。
